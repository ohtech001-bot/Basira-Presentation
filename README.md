# بصيرة — عرض شرائح سينمائي

تحديث 9 أكتوبر 2026 للمشروع الحالي المبني على React وTypeScript وVite. يضم العرض **15 شريحة كاملة المحتوى**: تظهر الصورة والعنوان والنص معًا عند دخول الشريحة، مع حركة قصيرة وهادئة. كل ضغطة على «التالي» تنتقل مباشرة إلى الشريحة التالية؛ الوصول من الأولى إلى الأخيرة يحتاج **14 ضغطة**. أُلغيت مراحل الكشف اليدوية والشاشات الفارغة التي كانت تجعل النسخة السابقة تتطلب 75 انتقالًا عبر 76 خطوة.

يحافظ العرض على المحتوى المعتمد في ملف الشرح: المشكلة، الحل وتجربة المنظومة، الفئات المستهدفة، الأهداف والأثر، خطة التنفيذ، التكلفة، أعضاء الفريق والرؤية. الواجهة عربية RTL، ومسرح العرض بنسبة 16:9 ومرجع 1920×1080.

## تشغيل العرض

يحتاج المشروع إلى Node.js 22.12 أو أحدث. افتح Terminal داخل مجلد المشروع:

```powershell
npm ci
npm run dev
```

افتح الرابط الذي يظهر في نافذة الأوامر، أو انقر مرتين على `عرض-بصيرة.cmd` بعد تثبيت الحزم لفتح العرض تلقائيًا. اترك نافذة الخادم مفتوحة أثناء العرض. تبدأ الشريحة الأولى بصورة المعلم والسؤالين؛ لا تحتاج نقرة إضافية لإظهار محتواها. قد تظهر حالة تجهيز قصيرة أثناء تحميل صورة البداية والشعار.

لإنشاء نسخة الإنتاج ومعاينتها:

```powershell
npm run build
npm run preview
```

ملفات النشر تظهر في `dist/` وتحتاج إلى خادم؛ لا تفتح `dist/index.html` مباشرة. جميع الصور محلية، ولا يحتاج العرض إلى اتصال بالإنترنت بعد تثبيت الحزم.

## التحكم

| المفتاح                     | الوظيفة                    |
| --------------------------- | -------------------------- |
| السهم الأيمن `→` أو `Space` | الشريحة التالية مباشرة     |
| السهم الأيسر `←`            | الشريحة السابقة مباشرة     |
| `F`                         | تبديل ملء الشاشة           |
| `Escape`                    | الخروج من ملء الشاشة       |
| `Home`                      | الشريحة الأولى             |
| `End`                       | الشريحة الأخيرة            |
| `R`                         | إعادة ظهور الشريحة الحالية |

تظهر أدوات المقدم عند تحريك المؤشر أسفل الشاشة: السابق، التالي، رقم الشريحة، إعادة الشريحة وملء الشاشة. يمكن الانتقال فورًا دون انتظار انتهاء الأنيميشن. الخط الذهبي السفلي يعكس موضع الشريحة، ولا ينتقل العرض تلقائيًا بتوقيت ثابت.

تضم شريحة النموذج الأولي ستة اختيارات لمعاينة الواجهات؛ هذه المعاينات **اختيارية**، ولا يلزم فتحها للتقدم إلى الشريحة التالية. يظهر محتوى شريحة الأهداف كاملًا، مع PageFlip صغير يعمل تلقائيًا مرة واحدة ويحوّل صفحة القراءة إلى صورة تجربة المنظومة.

## صور المنظومة والهوية

تحتوي `ui/` الآن على **17 صورة أصلية**: **15 واجهة للمنظومة**، الشعار `logo.jpeg`، وصورة `qaytbay-sabil.jpg`. اعتمدت الصور الجديدة ذات الأسماء الواضحة مثل `الرئيسية.png` و`الخريطة التفاعلية.jpg` و`شرح سبيل قايتباي.png`. بقيت الأصول كما وردت دون تعديل داخل `ui/`.

تستخدم الشرائح الخريطة المركزية `src/data/uiAssets.ts` ومكوّن `UiImage`. تحفظ الخريطة اسم الأصل `sourceFile`، واسم النسخة المعروضة `servedFile`، وأبعاد الأصل والنسخة. تُعرض واجهات المنظومة كاملة باستخدام `contain` دون تشويه أو قص. الشعار الأصلي محفوظ مطابقًا للملف الأصلي بأبعاده 1254×1254 وألوانه.

خفّضت نسخ العرض حجم الصور من **71.38 MB إلى 7.77 MB**، أي **89.11%**: 11 نسخة WebP للصور الثقيلة، و6 ملفات JPEG محفوظة كما وردت تشمل الشعار والواجهات الصغيرة. صارت الواجهات الكبيرة الأربع 1920×1081، وصورة المعلم 1280×1920؛ بقيت بقية الواجهات 1672×941. التحسين يغيّر الحجم أو صيغة الضغط فقط، ويحافظ على محتوى الصورة وإطارها والنسبة الأصلية.

يحمّل العرض أصول الشريحة الحالية والتالية مسبقًا بحد أقصى عمليتي تحميل متزامنتين، وتبقى بقية الصور عند الطلب. فشل صورة يعرض بديلًا دون أيقونة مكسورة، ولا يمنع التنقل. يوضح [تقرير الأصول](ASSET_REPORT.md) الاستخدام الفعلي لكل صورة، بما فيها الصور المتاحة التي لم تُدرج في الشرائح.

الجرد التفصيلي في `previews/asset-inventory.json`، ولوحة صور المراجعة في `previews/asset-contact-sheet.jpg`. يعيد `scripts/inspect_assets.py` تجهيز نسخ الصور والجرد باستخدام Pillow؛ يجب تحديث خريطة الأسماء والأبعاد عند تغيير الملفات الأصلية.

## البيانات المعتمدة والحركة

الميزانية الرسمية في `src/data/budget.ts`: تأسيس 6,000 ₪، دون أجور أعضاء الفريق، وتشغيل حتى 300 ₪ شهريًا للاستضافة والسيرفرات والحماية والرابط. لا يعرض المشروع تقسيمات تكلفة غير معتمدة.

تضم خطة التنفيذ: جمع المعلومات الموثوقة خلال 3 أسابيع إلى شهر؛ بناء النماذج ثلاثية الأبعاد خلال 40–50 يومًا؛ بناء المحاكاة والتحديات خلال شهر إلى 40 يومًا؛ ثم الاختبار والنشر والتطوير المستمر. أسماء الفريق محفوظة في `src/data/team.ts` دون مناصب غير مؤكدة.

الانتقالات قصيرة مع مراعاة إعداد تقليل الحركة. يستخدم المشهد 11 وحده PageFlip؛ لا توجد حركة تقليب إلزامية بين الشرائح. صور الواجهات تمثل النموذج الأولي، وأرقام المنافسة والنقاط أمثلة داخل العرض. الصوت معطّل افتراضيًا، والوثائق والملفات الصوتية إضافات اختيارية.

## التحقق والتعديل

```powershell
npm run lint
npm test
npm run test:scenes
npm run build
```

تغطي الاختبارات التنقل بين الشرائح وحدود البداية والنهاية، وPageFlip، وسلامة الصور الأصلية والنسخ المحسنة وأبعادها ونسبها. يفحص `test:scenes` مكونات الشرائح الخمسة عشر مباشرة دون متصفح. لم تتوفر مراجعة بصرية مباشرة للنسخة الحالية بسبب رفض سياسة أداة المتصفح؛ نتائج التحقق وحدودها موثقة في [QA.md](QA.md).

ملفات المحتوى في `src/scenes/`، والهوية والتخطيط في `src/styles/`، والمكونات المشتركة ومحرك العرض في `src/components/` و`src/hooks/`. عند تعديل محتوى شريحة، أبقه ظاهرًا مع دخولها، وأبقِ التنقل ضغطة واحدة لكل شريحة.

## المشاركة عبر GitHub Pages

اتبع [دليل GitHub Pages](GITHUB_PAGES.md). ارفع محتويات المشروع إلى جذر المستودع على فرع `main`، بما فيها `.github` و`ui` و`public` و`package-lock.json`، واستثنِ `node_modules` و`dist`. اختر **Settings → Pages → Source → GitHub Actions**، ثم شغّل **Publish Basira to GitHub Pages** من تبويب Actions.

يبني `.github/workflows/deploy.yml` المشروع ويختبره، ثم ينشر محتويات `dist` بمسار GitHub Pages الصحيح. الرابط المحلي `127.0.0.1` يعمل على جهازك فقط؛ رابط Pages المنشور هو الرابط الذي ترسله لأصدقائك.
